Mission control v2 — sessions are the unit

The conceptual model. The session is the primary unit of work — the actual moment of AI activity. A project is a container of sessions. A space is a container of projects. Artifacts are siblings to sessions — durable outputs that one or more sessions produced. Memories are background.

Primary unit
Session
A discrete moment of AI work. Has a title, project, time, state.
Sibling unit
Artifact
A durable output produced by 1+ sessions. Notes, app, deck, diagram, etc.
Container
Project
A folder on disk. Holds the sessions + artifacts that happened there.
Container of containers
Space
A bucket for projects. Optional — exists when the user wants grouping.

So Home shouldn't be a grid of project tiles — that puts the container in front of the unit. Home should be a session timeline with project as context and artifacts as inline products. Projects and spaces become filters in the breadcrumb, not the primary nav structure.

Why this fits the model. Each row is one session — the primary unit. Project name is context (which folder it happened in), not a navigation step. Artifacts appear as inline chips on the session that produced them — visible without being a separate column. Same project can appear multiple times in the timeline (because the user worked there multiple times) — natural, no deduping needed. Time buckets (Today / Yesterday / This week) give visual rhythm and keep the list scannable for users with 100s of sessions. Ghost projects' sessions still appear, just dimmer with a "no folder" cue — history isn't hidden, just visually de-prioritised.
Variant · Artifacts-on-Home question
Should artifacts get their own list, or only inline-as-chips?
Inline-as-chips (above) keeps the timeline session-centric and shows the artifact as a product of its session. A separate "Recent artifacts" section would foreground artifacts as a parallel work axis — useful for the user who thinks "where's that doc I was working on" before "where's that conversation."
Inline-only (Scene 1) — artifacts are products visible on their producing session. No separate gallery. Best when sessions are the dominant mental model and artifacts are byproducts.

Inline + separate "Recent artifacts" section — artifact chips on session rows AND a section showing the N most recently created/updated artifacts. Best when users return to specific outputs (a deck, a doc, a published thing) more often than they return to the conversations.

Open question. Pick one for 1.0 — I'd lean inline-only since memories are explicitly de-prioritised and a dedicated artifacts section might be premature. Easy to add later.
What changes vs. the tile-grid Home. The unit shifts from project to session. Projects become the "where" label on each row, not the page's structuring entity. Same project legitimately appears multiple times — once per session — because a day's work in oyster-dev is multiple distinct moments. Spaces (when the user creates them) become a breadcrumb filter, not a nav prerequisite. Memories don't get a section because they're background. Artifacts get visibility via inline chips on the session that produced them — they ride along with the unit they're descended from.
